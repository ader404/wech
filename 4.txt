PART 15 — SIGNED ACTIVATION
==================================================

Do not simply trust a boolean response like:

{
  "valid": true
}

Use cryptographically signed activation responses.

Prefer asymmetric cryptography.

For example:

License API:
Private key signs activation payload.

Desktop:
Contains ONLY the public key.

Desktop verifies the signature locally.

Never embed the private signing key inside the desktop application.

The activation payload can contain:

- license ID
- customer ID
- device fingerprint hash
- issuedAt
- expiresAt
- license type
- feature permissions
- application version requirements

This allows the desktop application to verify activation even while offline.

Do NOT make the application randomly stop working while the customer is legitimately offline.
